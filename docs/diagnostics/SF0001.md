# SF0001: an unexpected operation failed

- **Symbolic key:** `generic.unexpected-operation`
- **Registry status:** `ACTIVE`
- **Release status:** Unreleased. The development Fabric server and client
  artifacts emit generic SF0001 diagnostics for verified failure observations;
  specialized classification and full runtime matrix evidence are pending.
- **Meaning:** Reports an unexpected operation failure when no safe specialized diagnosis is available.
- **Required evidence:** Verified operation scope, redacted exception type when available, and trace preservation facts only.
- **Fallback:** Emit SF0001 without inferred cause or blame; if completion fails, emit the original event unchanged.
- **Remediation ceiling:** `INSPECT_ONLY`
- **Allowed actions:** `CREATE_SANITIZED_SUPPORT_BUNDLE`,
  `INSPECT_CORRELATED_TRACE`. The bundle action is a registered permission,
  not a shipped command; [issue #36](https://github.com/MinecraftProt/Stackframe/issues/36)
  will implement it.
- **Registry source:** [SF0001 in the generated catalog](../diagnostic-registry/catalog.md#sf0001-unexpected-operation)

## What it means

Stackframe has evidence that an operation failed but cannot safely select a more
specific explanation. This can happen for an unfamiliar failure or when
specialized candidates have weak or conflicting evidence. The code does not
identify a faulty mod, file, server, or cause. A new diagnostic may be warranted
after a reproducible case supplies stronger evidence.

## Plain example

This is an illustrative ANSI-free payload matching the current generic Fabric
adapter; the ID is synthetic:

```text
error[SF0001]: an unexpected operation failed
trace: complete details preserved as diagnostic C9012E0000000000; diagnostic
  DC9012E0000000000; correlation C9012E0000000000
```

The original Log4j event and private full-trace file retain the exception
class, message, causes, suppressed exceptions, and frames. The supplemental
summary does not infer a root cause or mod owner. A `trace:` line must not claim
a saved record when the write failed.

## Safe checks

1. Keep the original error in `latest.log` or the loader's log and note the
   operation, time, code, and correlation ID. Do not discard the original stack
   trace because this summary is short.
2. If the trace state says details were preserved, use
   [full-trace lookup](../TROUBLESHOOTING.md#find-the-full-trace) locally. A raw
   trace may contain secrets; do not post it unchanged.
3. Compare exact Minecraft, Java, Fabric Loader, Stackframe, and relevant mod
   versions with the artifact's published compatibility evidence. Reduce to a
   safe reproducible case only after backing up affected data.
4. Search the issue tracker by `SF0001` and a sanitized exception class or
   operation. If no specific issue matches, prepare a
   [sanitized report](../TROUBLESHOOTING.md#prepare-a-sanitized-report).

## Recovery actions and limits

This code authorizes inspection only. It does not justify deleting world files,
removing mods, editing configuration, granting broad permissions, or restoring a
backup. Those actions can change data or availability and require independent
evidence, a current backup, and the relevant specialized guidance. Do not infer
blame from the first non-Minecraft stack frame.

If Stackframe itself cannot complete even this generic diagnostic, expect the
original event unchanged and a separate Stackframe failure notice where
possible. That [formatter fallback](../TROUBLESHOOTING.md#unknown-diagnostic-or-formatter-fallback)
may have no `SF0001` header; it is a different path.
